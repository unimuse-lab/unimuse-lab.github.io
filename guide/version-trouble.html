バージョンが違う・エラーが出たときの切り分け

改変で詰まる原因のほとんどは「バージョンの不一致」か「導入したものの競合」です。焦って全部入れ直す前に、このページの順番で確認してください。

切り分けの基本： エラーが出たら、まず Unity の Console（下部のタブ）にある赤いエラーの文章を読みます。最初の1件が根本原因で、後ろはその巻き添えのことが多いです。エラーの文章は選択してコピーできます。

症状1：「Unityのバージョンが違います」と言われる

確認するところ

  • Unity Hub の Installs で、使っている Unity が 2022.3.22f1 になっているか
  • VCC の Settings → Unity で指定されている Unity が同じ版か
  • プロジェクトを作ったときの Unity と、今開いている Unity が同じ版か

対処

  1. 違う版で作ってしまったプロジェクトは、そのまま開かず、VCC から 2022.3.22f1 でプロジェクトを作り直すのが安全です（版をまたいで開くと、自動変換で中身が変わって戻せなくなります）。
  2. Unity Hub に 2022.3.22f1 が無ければ、VCC の案内から追加インストールします。

症状2：プロジェクトを開くと赤いエラーが大量に出る

確認するところ

  • Console の最初の赤エラーに、導入したツールやアセットの名前が含まれていないか
  • そのツールが要求する SDK のバージョン（BOOTH の商品説明に書かれていることが多いです）
  • VCC のプロジェクト画面で、SDK（VRChat SDK）が最新になっているか

対処

  1. VCC でプロジェクトの SDK を更新してから、もう一度 Unity で開きます。
  2. 特定のツールを入れた直後から出る場合は、そのツールの説明にある前提（Modular Avatar が必要、など）を入れ忘れていないか確認します。
  3. それでも消えない場合は、入れた順番とエラーの文章をメモしてから調べます。手当たり次第に消すと原因が分からなくなります。

症状3：VCCが「Unityが見つからない」と言う

確認するところ

  • Unity Hub がインストールされているか（VCC は Hub 経由で Unity を探します）
  • Unity Hub 側で 2022.3.22f1 がインストール済みになっているか

対処

  1. Unity Hub を先にインストールし、Hub の Installs に 2022.3.22f1 を追加します。
  2. VCC の Settings → Unity から、Hub に登録された Unity を指定し直します。

症状4：アセットを入れたら別のツールが動かなくなった

確認するところ

  • 同じ役割のツールを2つ入れていないか（例：同種のエディタ拡張の重複）
  • アセット同梱の古い SDK やプラグインが、プロジェクト側の新しいものと競合していないか

対処

  1. アセットの .unitypackage を入れるときは、中身のチェックを外せる画面で「SDK」「Plugins」のような同梱物が無いか先に確認します。
  2. 競合が疑われる場合は、片方を外してエラーが消えるかで切り分けます（プロジェクトのコピーを取ってから試すと安全です）。
作業前のバックアップは、プロジェクトのフォルダごとコピーしておくだけで大丈夫です。詰まったときに「昨日の状態に戻れる」だけで、切り分けがだいぶ楽になります。

それでも分からないとき

エラーの文章（最初の赤いエラー1件）をそのままコピーして検索するのが一番の近道です。調べるときは、使っている Unity の版（2022.3.22f1）と SDK のバージョンも一緒にメモしておくと、同じ症状の情報にたどり着きやすくなります。

環境構築からやり直したい場合は 環境構築：UnityとVRChat SDKの準備 に戻ってください。
